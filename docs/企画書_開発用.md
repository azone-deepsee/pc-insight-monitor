# PC Insight Monitor 企画書（開発用）

**バージョン:** α版 v1.2.1  
**最終更新:** 2026-07-21  
**ステータス:** 有用性確認フェーズ（調査用ツール）

---

## 1. 概要

### 1.1 ツール名

**PC Insight Monitor**

### 1.2 目的

現場PCで USB / COM トラブル調査時に、複数の情報源（デバイスマネージャ相当の情報、Windowsイベントログ、QRツールの接続ログなど）を **1本の時間軸** にまとめ、原因究明を支援する。

### 1.3 位置づけ

| 項目 | 内容 |
|------|------|
| 種別 | 調査用ツール（手動起動） |
| 対象 | 業務用PC（Python インストール不可） |
| 配布形態 | ファイルサーバ上のフォルダ + ポータブル Python |
| QRツールとの関係 | exe 改修なし。ログ連携で統合 |

### 1.4 開発背景

USB調査時、以下を頭の中で時系列に並べて原因を推測していた。

- イベントビューア
- PowerShell / デバイス情報
- USB電流計（手動確認）
- Python QRツールの接続ログ
- 現場操作

本ツールはこの「頭の中での分析」をシステム化する。

---

## 2. 制約・方針

### 2.1 運用制約

| 制約 | 対応 |
|------|------|
| 業務PCへ Python インストール不可 | ポータブル Python を同梱（案B） |
| exe 配布は社内方針上避けたい | exe 化しない |
| Webサーバ起動は避けたい | tkinter デスクトップ UI |
| PowerShell 実行は可 | USB/COM 情報取得に使用 |
| python.exe 実行は可 | ポータブル版をネットワークパスから実行 |

### 2.2 設計方針

1. **監視と制御の分離** — 本ツールは監視専門。COM再接続などの制御は業務アプリ側。
2. **小さく作り現場で育てる** — α版は調査時の手動起動に限定。
3. **QRツールを触らない** — 機能統合ではなくログ統合で連携。
4. **ログはローカル保存** — ファイルサーバへの常時書き込みは行わない（負荷・競合回避）。

## 3. α版 v1.0 仕様

### 3.1 システム構成

```text
run.bat
  └─ python\python.exe（ポータブル Python 3.12）
       └─ run.py（tkinter UI）
            ├─ monitor/usb_watcher.py   … PowerShell / Get-PnpDevice
            ├─ monitor/event_watcher.py … Windows イベントログ（System）
            ├─ monitor/qr_log_reader.py … QRツール CSV 取込
            └─ monitor/logger.py        … CSV ログ出力
```

### 3.2 データ取得元（PC 内のみ）

| ソース | 取得方法 | 間隔 |
|--------|----------|------|
| COMポート | `Get-PnpDevice -Class Ports` | 2秒 |
| USBデバイス | `Get-PnpDevice -Class USB` | 2秒 |
| イベントログ | `win32evtlog`（System ログ） | 2秒 |
| QR接続ログ | CSV ファイル読込（手動取込） | 手動 |

**イベントログのフィルタ対象（部分一致）:**

- Kernel-PnP
- Kernel-USB
- USBHUB
- USBXHCI
- PnP / USB 関連

### 3.3 UI 機能

| 画面 / 操作 | 内容 |
|-------------|------|
| 概要 | 使い方・配布手順の説明 |
| COM一覧 | FriendlyName / Status / InstanceId |
| USB一覧 | 同上 |
| タイムライン | 全イベントを時系列表示（最大500件） |
| イベントログ | USB関連の System ログ直近100件 |
| 監視開始 / 停止 | バックグラウンド監視の ON/OFF |
| 一覧を更新 | 手動でデバイス一覧を更新 |
| QRログ取込 | config.json 指定フォルダの CSV をタイムラインへ統合 |

**上部サマリー表示:**

- COM総数 / COM正常 / COM Unknown
- USB総数
- タイムライン件数
- 監視状態（停止中 / 監視中）

### 3.4 統一イベント形式

すべての監視結果は `MonitorEvent` に正規化される。

| フィールド | 説明 |
|------------|------|
| timestamp | 発生日時 |
| source | COM / USB / EventLog / QRログ など |
| category | port / device / イベントソース名 など |
| message | 内容 |
| severity | info / warning / error |

### 3.5 ログ出力

| 項目 | 内容 |
|------|------|
| 保存先 | `%LOCALAPPDATA%\PCInsightMonitor\logs\` |
| 形式 | CSV（UTF-8 BOM） |
| ファイル名 | `session_YYYYMMDD_HHMMSS.csv` |
| 備考 | 各PCローカルに保存。ファイルサーバへは書かない |

### 3.6 設定ファイル（config.json）

```json
{
  "qr_log": {
    "enabled": false,
    "directory": "",
    "pattern": "*.csv"
  }
}
```

| キー | 説明 |
|------|------|
| qr_log.directory | QRツールの USB 接続ログ CSV があるフォルダ |
| qr_log.pattern | 取込対象ファイル（デフォルト: `*.csv`） |

### 3.7 文字エンコーディング

日本語 Windows 環境向けに PowerShell 出力は **cp932 → UTF-8** の順でデコードを試行。

## 5. 配布・セットアップ手順

### 5.1 開発PC（初回のみ）

1. 本リポジトリを clone
2. `setup_portable.bat` を実行（既存 Python 3.12 から必要最小限だけコピーし、pywin32 等を `python\` に配置）
3. `run.bat` で動作確認

### 5.2 ファイルサーバ配布

1. `pc_insight_monitor` フォルダ一式をコピー（`python\` 含む）
2. 現場PCでは `run.bat` をダブルクリック

### 5.3 GitHub 管理方針

| 管理する | 管理しない |
|----------|------------|
| ソースコード | `python\` フォルダ（体積大・環境依存） |
| バッチ・設定 | セッションログ |
| ドキュメント | |

## 6. 使い方（調査フロー）

### 6.1 基本フロー

1. トラブル発生前後を想定し、**監視開始** を押す
2. 現象を再現する（USB抜き差し、COM異常など）
3. **タイムライン** タブで時系列を確認
4. 必要に応じ **QRログ取込** で既存 CSV を統合
5. 調査終了後、CSVログを `%LOCALAPPDATA%\PCInsightMonitor\logs\` から回収

### 6.2 QRツール連携フロー

1. QRツールのログフォルダを `config.json` に設定
2. 調査開始後「QRログ取込」を実行
3. QRツールの接続/遮断ログとイベントログを同一タイムラインで比較

### 6.3 読み方の例

```text
15:59:58  QRログ      disconnect   COM4 遮断
16:00:00  EventLog    Kernel-PnP   [219] デバイス構成変更
16:00:01  COM         port         COM4 が OK → Unknown に変化
```

## 8. 技術メモ

### 8.1 既知の制限

- イベントログは起動**以降**の新規イベントのみ取得（過去ログは取込まない）
- QRログパーサは汎用実装のため、CSV形式によっては調整が必要
- ネットワークパス上のポータブル Python 実行は、環境によって初回起動が遅い場合あり
- 管理者権限がなくても多くの情報は取得可能だが、一部イベントは権限依存

### 8.2 依存関係

| パッケージ | 用途 |
|------------|------|
| pywin32 | Windows イベントログ読取 |
| tkinter | UI（Python 標準） |

### 8.3 開発時の実行方法

ポータブル Python 未セットアップ時は、開発PCのシステム Python でも `run.bat` が起動する（フォールバック）。

## 9. 関連ツールとの比較

| 方式 | メリット | デメリット |
|------|----------|------------|
| QRツールへ機能統合 | 1つで完結 | 全PCの exe 差し替えが必要 |
| 本ツール（別アプリ） | 展開が速い、QRツール無改修 | ツールが2つになる |
| exe 化 | 配布が単純 | 社内ポリシー上困難 |
| ポータブル Python（採用） | インストール不要、ソース流用可 | 初回セットアップが必要 |
