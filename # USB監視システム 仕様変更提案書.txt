# USB監視システム 仕様変更提案書

## 1. 背景

現在開発中のUSB監視システムは、**Pythonによるデスクトップアプリケーション**として開発を進めている。

USB機器やCOMポート、Windowsイベントログなどの監視機能は実装が進んでいるが、今後の運用性・保守性・拡張性を考慮し、システム構成を見直す。

本システムは、**PC自身の状態を監視・診断するツール**であるため、診断システム自身がPCへ与える負荷を最小限に抑えることを最優先とする。

---

# 2. 現状構成

```
Python

├─ Python GUI
│
├─ USB監視
├─ COM監視
├─ イベントログ監視
├─ PC情報取得
└─ ログ保存
```

### 特徴

* UIをPythonで構築
* 監視処理もPythonで実装
* Python実行環境（Portable Python）を利用
* 将来的な機能追加を想定

---

# 3. 現状の課題

## ① Python GUIの保守性

画面レイアウトやデザイン変更のたびにPythonコードを修正する必要がある。

画面設計と監視処理が密結合となっており、機能追加時の影響範囲が大きい。

---

## ② Portable Pythonによる配布

Python実行環境を同梱するため、

* 配布容量が大きい
* 管理ファイルが多い
* 利用者には不要なファイルまで配布される

という課題がある。

---

## ③ UIと監視処理が一体化

UI更新処理と監視処理が同一プロセス内で動作するため、

将来的に監視項目が増えた場合、

* UIレスポンス低下
* 保守性低下

が懸念される。

---

## ④ 将来的な拡張性

今後追加予定である

* CPU監視
* メモリ監視
* USB電源監視
* AI診断
* ダッシュボード

などを考えると、

画面と監視処理を分離した構成が望ましい。

---

# 4. 要求事項

本システムは以下を満たす構成とする。

### システム負荷

* CPU負荷を最小限にする
* メモリ使用量を抑える
* ディスクアクセスを最小限にする

---

### ストレージ

* 配布サイズを小さくする
* 不要な実行環境を配布しない

---

### 通信

* インターネット不要
* LAN不要
* ローカルPCのみで動作

---

### 保守性

* UI変更を容易にする
* 監視ロジックと画面を分離する
* 将来の機能追加を容易にする

---

### 現場運用

* ダブルクリックで起動できる
* Pythonを意識しない運用とする

---

# 5. 提案内容

## システム構成の見直し

UIと監視処理を分離する。

### バックエンド

Pythonを継続利用し、

USB監視

COM監視

イベントログ取得

PC情報取得

ログ保存

など、Windows制御を担当する。

---

### フロントエンド

UIは

* HTML
* CSS
* JavaScript

で構築する。

画面表示はブラウザで行い、

Pythonとはlocalhost通信で接続する。

---

### PythonのEXE化

Pythonプログラムは配布時にEXE化する。

Portable Pythonは廃止する。

利用者はPython環境を意識する必要がなくなる。

---

# 6. 新構成

```
ブラウザ

        │

localhost通信

        │

USBMonitor.exe

        │

Python

├─ USB監視
├─ COM監視
├─ イベントログ監視
├─ PC情報取得
└─ API
```

---

# 7. 期待効果

## UI変更が容易

画面デザイン変更は

HTML

CSS

JavaScript

のみで対応できる。

監視処理への影響が少ない。

---

## 保守性向上

監視機能と画面機能を分離できる。

役割が明確となり、

機能追加時の修正範囲を限定できる。

---

## PC負荷低減

Pythonは監視処理のみを担当する。

ブラウザは画面表示のみとなるため、

システム全体の負荷を低く抑えられる。

---

## ストレージ削減

Portable Pythonを廃止し、

必要最小限の実行環境のみをEXEへ組み込むことで、

配布容量を削減できる。

---

## 通信環境非依存

通信はlocalhostのみ。

ネットワーク障害やインターネット接続の有無に影響されない。

---

## 将来の拡張性

監視機能の追加はPython側、

画面追加はHTML側で対応できる。

将来的な

* AI診断
* グラフ表示
* ダッシュボード
* 帳票出力

なども比較的容易に実装できる。

---

# 8. 結論

現在の**PythonによるGUIアプリケーション**から、**HTML/CSS/JavaScriptを用いたWeb UIと、Python（EXE化）によるバックエンドを分離した構成**へ移行することを提案する。

この構成により、以下の要求を満たすことが期待できる。

* PCへの負荷を最小限に抑える
* ストレージ消費を削減する
* 通信環境に依存しない
* UIの保守性・変更容易性を向上させる
* バックエンド機能の拡張性を確保する
* 現場への配布・更新を容易にする

この構成は、現在のUSB監視ツールだけでなく、将来的な「PC診断プラットフォーム」としても発展しやすいアーキテクチャとなります。
